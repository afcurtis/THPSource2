## What the career state is

The career lives in a handful of retail globals that refer to one another by address, so the
native port keeps them where retail does. `RetailMemory` (`src/runtime/retail_memory.hpp`) is a
sparse set of byte regions at retail addresses; every ported function reads and writes it at those
addresses and reaches the outside world (assertions, sound, on-screen messages, random numbers,
"is a movie playing") through `RetailServices`, which reports each reach as a named call and hands
back scripted values. A captured memory image therefore replays word for word.

```text
career record (per character, 0x104 bytes at 0x00568a6c + character * 0x104; 21 exist)
  +0x00 u8   tapes: goals collected over the non-contest levels
  +0x01 u8   flags (0x40: the game was cleared with this character)
  +0x03 u8   contest levels won gold
  +0x04 s32  all cash ever earned       +0x08 s32  cash to spend
  +0x0c u16[13]  per level: bits 0-9 goals, 0x400 gold, 0x800 silver, 0x1000 bronze, 0x8000 cleared
  +0x26 u8[13]   (set to 0xff by Career_ClearGame, no reader recovered)
  +0x34 u32  trick-class mask (1, or 0x3ff for a custom skater)
  +0x38 s8[10]   stat points bought
  +0x44 u32[26]  cash icons collected: two words per level
  +0xac u32[4]   purchased-trick bitmap     +0xcc  the 0x35-byte binding block

level table (`levels`, 0x0053c1f8, 13 records of 0x1ac bytes, static)
  +0x00 name  +0x48 u8 contest flag  +0x50/+0x54/+0x58 judging thresholds  +0x5c/+0x60/+0x64 gold /
  silver / bronze prize money  +0x7c cash needed to open  +0x80 levels-with-medals needed (when
  nonzero)  +0xb0/+0xb4 the level's gap id range (ids are taken mod 10000)
  +0xb8 + goal * 0x18 (10 rows): +0 type (0 score, 1 SKATE, 2 gap goal, 3 pickups, 4 count,
  5 trick gaps, 6 secret tape, 7 everything)  +4 score threshold  +8 noun pointer  +0xc reward
  +0x10 description pointer

live per-level state (0x0055fd2c ...): goals got this run (0x0055fd7c), goal / trick gaps got
(0x0055fd30 / 0x0055fde0), their counts (0x0055fdd8 / 0x0055fe04), cash icons in the level
(0x0055fe08), pickups (0x0055faf0 / 0x0055fd80), the highest open level (0x0055fd78), progress
message buffers (0x0055fd34, 0x0055fd54, 0x0055fde4)
gap bits (0x0056a23c, three words per level), cheat list (0x0056a374, 17 entries of 4 bytes:
unlocked, the character that earned it, on/off)
```

The "current character" of the career code is the skater manager's active slot
(`SkaterManager_CurrentCharacter`); the player object (`0x0056a858`) supplies the score
(`+0x16c`), the character for cash icons and medals (`+0x2cc0`) and the tape counters.

## Functions

The full address-to-native table is in the slice manifests (`re/slices/career-progress.yml`,
`career-cheats.yml`) and `re/native/functions.yml`; names are curated in `re/symbols/functions.yml`.

**Goals and medals.** `Career_GiveGoal` (`0x004142e0`) plays sound `0x17c`, shows the goal's
description, sets the goal bit in the run mask and in the record's level mask, recounts the
record's tapes over the non-contest levels, adds the reward to both cash words, bumps the skater's
tape counter and ends with `Career_CheckClear`. `Career_CheckClear` marks a contest level
cleared (`0x8000`) or, on an ordinary level whose cash icons are all in and with nine goals,
awards the "100%" goal. `Career_GiveMedal` sets the medal bit and recounts golds.

**Gaps.** A level's gaps are the records of the active gap table whose id (mod 10000) falls in
the level's range; goal gaps (kind 1) and trick gaps (kind 2) are numbered among their own kind.
Awarding the last goal gap awards the gaps goal, otherwise a "n of m NOUN" message is shown.

**Cash icons.** The icon's number is the high byte of a word in its trigger node (written at
level load by `Career_CountThings`, which also tallies the level's gaps and pickups and the
highest open level). While a movie plays the icon mask is the scratch copy at `0x00568608`.

**Levels.** A level is open for a record when the cash earned reaches each earlier level's
requirement, or (where the table says so) enough contest levels have medals; levels 10, 11, 12
open on a gold in contest levels 2, 5, 7; the "all levels" cheat opens everything. Outside career
mode any character's record opens a level.

**Stat points.** Buying a point costs `((bought - base - 5) * 5 + 5) * 10` cash (a custom skater
spends its own spare points instead); the price is computed from the points already held, so a
sale refunds the price of the point below it.

**Cheats.** `Career_UnlockCheat(cheat, character)` also releases the secret character the cheat
belongs to; the cheat state switches have side effects (kid mode and big head exclude each
other; disco mode, level flip, wireframe, ...) which the port reports as service calls where they
reach other subsystems.

## Validation method

Nothing in a natural career run exercises more than a sliver of this code, so the functions are
**forced-called in the running game**: `re/gdb/probes/career_calls.py` stops the retail process
(Warehouse) at a physics frame, snapshots the memory regions the native code touches, then for each
function pokes a random but legal career state (records, manager, level, game mode, player), calls
the retail function through a GDB inferior call with the outside services stubbed
(`re/gdb/opentony/fcall.py`), records the return value, every byte the call wrote and the ordered
service calls, and restores memory. `scripts/make_career_calls_fixture.py` turns that into a fixture
and `src/runtime/career_retail_calls_test.cpp` replays each case from the same pre-state through the
native port; return value, written bytes and service calls must all match, and a changed fixture
value makes the test fail (`tests/test_career.py`).

What this proves and what it does not: it proves the port equals retail on the states the
generators reach, which include the out-of-range arguments and asserts that matter, but they are
generated states, not a played game; the natural-play capture of these functions (a whole career)
is not attempted. Stubbed services (sound, messages, random numbers, the movie flag) are seams:
their own behaviour is not claimed.

## Corrections found on the way

- `Career_AwardGoalGap` ends its "all gaps" branch with `Career_GiveGoalType(2)`; the decompiler
  dropped the argument. `Career_ToggleCheat(cheat, apply)` passes its second argument through as
  `Career_SetCheat`'s third. Both were read from the disassembly.
- The "not a goal gap" assertion in `Career_GapGoalNumber` tests `Career_GapActive`, not
  `Career_GapIsGoal`; the message is wrong for the test it guards.
- `Career_ClearGame` and `Career_CountGaps` walk only levels 0..7 (their loops end at
  `0x0053cf9f` and `0x0056a29c`), and `Career_UnlockCharacter` / `Career_CaptureSkaterDefaults` /
  `Career_ResetRuntimeState` walk 21 skater rows (the loop ends at `0x0053c1d4`).
- A fault in `ClearGame`: the mask it writes for a contest level is `0x9801 + 0x3ff = 0x9c00`
  (gold, silver, bronze and cleared), not `0x3ff`.

(The retail-replay counts and any divergences found are in the slice completion notes.)
