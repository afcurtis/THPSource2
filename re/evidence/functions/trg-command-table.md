This is the concrete opcode table and dispatch structure the 4.4b work (wiring

## Sources of truth

1. The retail dispatcher `0x004c5dc0` decides every operand width. The Ghidra
   dump is `build/p44/dispatcher.c` (scratch, regenerate with `tony ghidra`).
2. `thps2-tools` `disassemble-trg.py` (MIT, pinned in `re/xref/config.yml`) is an
   independent disassembler written from the PSX-era format. Across the 32
   shipped files, 3588 of 3594 command streams tokenise identically in the
   Python decoder (`tony/assets.py`) and in that tool; the six exceptions are the
   dead nodes described below. It is used as a cross-check for names and widths,
   never as the authority.
3. NeverScript targets the THPS3/4/THUG QB format and does not describe THPS2
   TRG. It is pinned only so nobody re-evaluates it.

## Stream framing

- A type-6 (CommandPoint) node is `type, link_count, links[], padding,
  u32 checksum, u16 commands[] ... 0xffff`. Type-4/15 (AutoExec) and type-8
  (Restart) nodes carry a command stream after their own fixed payload; the
  stream start is computed in `TrgFile::script()` / `_trg_script_start`.
- A stream ends at opcode `0xffff`. Operands are little-endian u16 words unless
  a command is marked *aligned*, in which case the cursor is first aligned down
  to four bytes at `(opcode_offset + 5) & ~3` (`0xab`, `0xc9`) or
  `(cursor + 3) & ~3` per record (`0x85`, `0x8d`).
- Commands `0x03 0x04 0x05 0x0a 0x0b 0x0c` have **no** stream operand: their
  targets are the source node's serialized link list, filtered by the helper to
  node types 1 (baddy) and 7. Only `0x0d` takes one u16. See
  `trg-counted-link-commands.md`.
- `0x04` is *activate* (`CBody::UnSuspend`, `0x004803b0`) and `0x05` is
  *suspend* (`CBody::Suspend`, `0x004802f0`). Earlier code had them swapped.
- The camera and PlayXA commands `0x82 0x87 0x8b 0x8f 0x90 0x91 0x92` advance
  three words (opcode plus two operands); `0x68` advances four words and its fog
  values are applied only after the whole stream has been walked.

## Native dispatch structure

`TriggerRuntime::dispatch()` in `src/trg/trg_runtime.cpp` is a single
`switch (opcode)` over a `CommandCursor`:

```text
loop until cursor at end of the source node
    opcode = read_u16()
    0xffff                   -> leave the loop
    0x94 / 0xcc / 0xcd       -> condition true: ++conditional_depth, keep going
                                condition false: skip_to_endif() (depth-aware,
                                counts nested 0x94/0xcc/0xcd, stops at 0x95)
    0x95                     -> --conditional_depth (diagnostic when 0)
    0x03                     -> pulse the source links unless the command
                                point's budget (set by 0x86) is zero; a finite
                                budget is decremented, 0xffff is unlimited
    0x68                     -> remember the fog triplet
    everything else          -> read the documented operands, call one
                                TriggerServices callback (or diagnose)
    unknown opcode           -> on_unknown_command + diagnostic, advance one
                                word (as retail's default arm), continue
after the loop: emit the pending fog triplet once via on_fog_range
```

Pulse propagation (`pulse_node`) re-enters `dispatch()` for the target node.
Command-point state (`pulse_count`, initial budget, checksum) lives in
`CommandPointRuntime`. `execute_restart()` applies the restart position and
auxiliary words through services and then dispatches the restart node's own
stream. Every retail-visible effect goes through `TriggerServices`
(`src/trg/trg_runtime.hpp`); 4.4b implements those callbacks against real
objects.

Names that disagree with thps2-tools are deliberate: `0x83`/`0x84` are named by
what the PC dispatcher does (clear/set an object flag by id) rather than the
PSX-era background labels; `0x9e` and `0x97` are named from the PC service they
reach. Rows whose native handling says *operands consumed* are commands whose
PC helper is empty or routes to an unavailable subsystem; consuming the verified
operands is the whole faithful behaviour.

## Retail skip walker versus dispatcher

`0x004c7c50` skips a command without executing it (used for false conditional
blocks). Its jump table is **not** a reliable width oracle: it has no case for
`0x96 0x97 0x98 0x9d 0x9e 0x9f 0xa1 0xa2` and falls into an assert
("Unknown command, need to update Skip…") for them, although the dispatcher
handles all of them. The native `skip_operands()` uses the dispatcher widths for
every opcode. A conditional block containing one of those commands therefore
skips correctly in the native runtime; do not port the walker's table.

## Dead 0x8d nodes in SKATE_T and SKPARK_T

Nodes 48, 49 and 50 of both `SKATE_T.TRG` and `SKPARK_T.TRG` are leftover
PSX-format `0x8d` records (empty link list, zero checksum) that the PC
dispatcher cannot tokenise. They look unreachable, but SendPulse nodes 27 and 42
link to nodes 49 and 50, so pulse propagation does reach them. Retail reads past
the node into the next bytes (not reproducible); the native decoder raises
`FormatError`.

**Resolved in 4.4b** (`trg-pulse-fault-isolation`): `TriggerRuntime` now catches
`FormatError` per linked pulse target, drops that pulse, reports a diagnostic and
counts it (`faulted_pulses()`). `opentony_trg_inspect --dispatch-all` reports
`undecodable=3` (only the direct pulses to nodes 48-50) and `faulted_pulses=2`
(nodes 27 and 42 reaching nodes 49 and 50) for those two files. A direct
`pulse_node` call on a dead node still throws. This remains a known asset hazard,
not a decoder bug.

## Status of the service boundary

The per-pulse `FormatError` catch is done; the level-object script interpreter,
object lists and message commands are in `object-script-vm.md`. `ScriptWorld`
(`src/trg/script_world.hpp`) runs the real objects inside `LevelRuntime`; the
`TriggerServices` callbacks it routes to are the state boundary.

- Keep decoding separate from the `TriggerServices` callbacks (the callbacks are
  the only state boundary).
- Catch `FormatError` per pulse (see above); the two known files must load.
- Unknown opcodes are non-fatal by design; none occur in the shipped corpus.
- `0x03`'s budget rules and the once-per-stream fog application are already
  native behaviour; do not move them into services.
- Service names left partial: score/checklist (`0xc9` deferred path), level
  event (`0x9e`), script objects (`0xab`), current-object field writes
  (`0x99..0xb1`). They have evidence docs; none needs a new width decision.
