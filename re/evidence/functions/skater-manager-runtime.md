# Skater manager (skatmgr.cpp)

Status: native port of all 30 functions of `skatmgr.cpp`, replayed against retail forced calls
(Phase 4.8; method in [career-runtime.md](career-runtime.md#validation-method))
Build: `f2c7ca7cbc31abd8f748bd4afdc1e30aa1a6700ce91893b618450fd16172669c`
Native: `src/runtime/skater_manager.{hpp,cpp}`, static tables `src/runtime/career_tables.cpp`
(generated by `scripts/generate_career_tables.py`)

The skater manager is one object at `0x0056c580` (0x6a0 bytes). It records, for each of eight
player slots, which of the twenty characters is picked, in which costume, and which custom skater
(0..3) the slot uses; and it can hold a loaded copy of a custom skater for a slot. The character
table it indexes is static data in `.data`; custom skaters live in 0x80-byte records.

## Memory model

```text
manager (0x0056c580)
  +0x04 + slot * 0x0c   slot entry: +0 character, +4 custom-skater slot, +8 costume      (8 slots)
  +0x64                 active slot (0..7)
  +0x68 + character * 4 the costume each character last wore                            (20)
  +0xb8 + slot * 0xbc   loaded-custom-skater flag (dword)                                (8)
  +0xbc + slot * 0xbc   the loaded 0x35-byte binding block (copy of career record +0xcc)
  +0xf4 + slot * 0xbc   the loaded 0x80-byte custom record (copy of 0x0056a488 + n * 0x80)
  +0x119 + slot * 0xbc  a flag byte inside that copy (record +0x25)

character table (SkaterModelNameTable, 0x0053a3b8, 20 rows of 0x170 bytes)
  +0x00 + i * 8         costume model-name pointer i (0..3); a null pointer is "no such costume"
  +0x20                 the display name ("Tony Hawk", ...), inline
  +0x144                ten base stat bytes
  +0x14f                a flag byte (SkaterManager_SlotIsSelectable)
  +0x150                pointer to the face bitmap name
  +0x158                "unlocked" dword
  +0x15c                flags: 0x02 custom skater, 0x08 / 0x10 costume list ends at two / three
                        entries until unlocked, 0x40 / 0x80 / 0x100 / 0x200 the secret
                        characters the cheats release
  +0x168                the ending-video id

custom record (0x0056a488 + n * 0x80)
  +0x00 name  +0x21 spare stat points (s8)  +0x22 flag  +0x25 flag  +0x26 valid (0 or 1; else corrupt)
  +0x2c ten stat dwords
```

## Behaviour worth recording

- Picking a character for a slot restores the costume that character last wore (the per-character
  table at +0x68); picking a costume both sets the slot's costume and remembers it for the
  character. A costume past the last wraps to the first when the caller asks for it.
- The number of costumes a character has is the count of non-null model-name pointers among the
  first four, cut short by the row flags: `0x08` stops the list at two, `0x10` at three (the
  unlock code clears both bits, see [career-runtime.md](career-runtime.md)).
- A custom skater's row is "custom" by flag bit `0x02`; its position among the custom rows
  (`Skater_CustomSlotIndex`) selects its 0x80-byte record, and `Skater_MapEnabledIndex` goes the
  other way (the n-th custom row). The loops that walk the table run to `0x0053c1d4`, which is
  21 rows: the twenty characters and a 21st "row" that is the bytes after the table.
- Every range check only logs (`M3dUtils_InBetween`, milestone 4.5): slot out of range,
  character out of range, bad costume index, "Not a custom skater", "Unused loaded skater". The
  port reports each as an `assert` service call and carries on, as retail does, and several
  callers assert twice because the helper they call asserts again.
- `Skater_SelectManagerSlot(-1)` means slot 0 ("the first player"); it is a plain wrapper that
  returns the slot's character.

## Open

- The byte at row `+0x14f` (`SkaterManager_SlotIsSelectable`) and the flags `0x20` / `0x02` of
  loaded records are named by use only; their meaning is a frontend matter (milestone 4.10).
- Slot entries 2..7 (players beyond the first two) were exercised only through forced state, never
  by a natural multi-player selection.
